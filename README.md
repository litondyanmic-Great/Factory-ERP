# ওয়ার্মলুম ইআরপি — সোয়েটার ফ্যাক্টরি ম্যানেজমেন্ট

প্রোডাকশন/মার্চেন্ডাইজিং ট্র্যাকিং এবং ইনভেন্টরি (ইয়ার্ন ও এক্সেসরিজ) ম্যানেজমেন্টের জন্য একটি
ওয়েব-বেজড ERP। ডিপার্টমেন্ট-ভিত্তিক অ্যাক্সেস কন্ট্রোল সহ (অ্যাডমিন, মার্চেন্ডাইজিং, প্রোডাকশন, স্টোর)।

ব্যাকএন্ড **Firebase** (Auth + Firestore — গুগলের প্রোডাক্ট, ফ্রি টায়ারেই যথেষ্ট) এবং হোস্টিং
**Netlify**-তে হবে। দুটোই ফ্রি প্ল্যানে শুরু করা যায়।

---

## যা যা আছে

- **প্রোডাকশন ট্র্যাকিং**: প্রতিটি স্টাইল/অর্ডারের জন্য ৬টি স্টেজ (নিটিং → লিংকিং → মেন্ডিং/ট্রিমিং →
  ওয়াশিং → ফিনিশিং → প্যাকিং) — প্রতিদিনের প্রোডাকশন এন্ট্রি ও অগ্রগতি একসাথে দেখা যায়।
- **ইনভেন্টরি**: ইয়ার্ন ও এক্সেসরিজের স্টক, স্টক-ইন/আউট এন্ট্রি, রি-অর্ডার লেভেলের নিচে নামলে
  ড্যাশবোর্ডে এলার্ট।
- **ইউজার ও ডিপার্টমেন্ট**: প্রথম অ্যাকাউন্টটি স্বয়ংক্রিয়ভাবে অ্যাডমিন হয়ে যায়। এরপর নতুন যে কেউ
  সাইন আপ করলে "অপেক্ষমাণ" অবস্থায় থাকে, যতক্ষণ না অ্যাডমিন তাকে অনুমোদন করে ডিপার্টমেন্ট
  (মার্চেন্ডাইজিং / প্রোডাকশন / স্টোর) ঠিক করে দেয়।
- ডেটা রিয়েল-টাইমে সিঙ্ক হয় — একজন এন্ট্রি দিলে বাকিরা সাথে সাথে দেখতে পাবে।

---

## ধাপ ১: Firebase প্রজেক্ট তৈরি করুন

1. [console.firebase.google.com](https://console.firebase.google.com) এ যান, Google অ্যাকাউন্ট
   দিয়ে লগইন করুন।
2. **"Add project"** ক্লিক করুন। নাম দিন (যেমন `sweater-erp`)। Google Analytics লাগবে না,
   বন্ধ রেখেই এগিয়ে যান।
3. প্রজেক্ট তৈরি হলে বাম পাশের মেনু থেকে **Build > Authentication** এ যান।
   - **Get started** ক্লিক করুন।
   - **Sign-in method** ট্যাবে গিয়ে **Email/Password** চালু (Enable) করুন।
4. বাম মেনু থেকে **Build > Firestore Database** এ যান।
   - **Create database** ক্লিক করুন।
   - Location হিসেবে কাছাকাছি একটা রিজিওন বেছে নিন (যেমন `asia-south1`)।
   - **Production mode** সিলেক্ট করে এগিয়ে যান (rules পরের ধাপে বসাবো)।
5. Firestore তৈরি হলে **Rules** ট্যাবে যান। এই প্রজেক্টের `firestore.rules` ফাইলের পুরো কন্টেন্ট
   কপি করে সেখানে পেস্ট করে **Publish** করুন। এই rules-গুলোই ঠিক করে দেয় কোন ডিপার্টমেন্ট কী করতে
   পারবে — এগুলো ছাড়া যেকেউ যেকোনো ডেটা পড়তে/লিখতে পারবে।

## ধাপ ২: Firebase থেকে কনফিগ কী সংগ্রহ করুন

1. Firebase কনসোলে প্রজেক্টের **Project settings** (গিয়ার আইকন) এ যান।
2. নিচে **"Your apps"** সেকশনে **Web (`</>`)** আইকনে ক্লিক করে একটা ওয়েব অ্যাপ যোগ করুন।
   নাম যা খুশি দিতে পারেন (যেমন `sweater-erp-web`)। Firebase Hosting সেটআপ করতে বলবে —
   এটা এড়িয়ে যান (Skip), কারণ হোস্টিং হবে Netlify-তে।
3. এখন যে কোড দেখাবে তার মধ্যে `firebaseConfig` অবজেক্টে থাকা মানগুলো (`apiKey`,
   `authDomain`, `projectId`, ইত্যাদি) কপি করে রাখুন।
4. এই প্রজেক্টের `.env.example` ফাইলটা কপি করে নাম দিন `.env`, এবং প্রতিটা ভ্যালু বসিয়ে দিন:

   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_STORAGE_BUCKET=...
   VITE_FIREBASE_MESSAGING_SENDER_ID=...
   VITE_FIREBASE_APP_ID=...
   ```

   এই মানগুলো পাবলিক ফ্রন্টএন্ড কোডে থাকা নিরাপদ — আসল সিকিউরিটি Firestore rules দিয়েই নিয়ন্ত্রিত
   হয়, এই কী দিয়ে নয়।

## ধাপ ৩: লোকাল কম্পিউটারে চালিয়ে দেখুন (ঐচ্ছিক)

```bash
npm install
npm run dev
```

ব্রাউজারে `http://localhost:5173` খুলুন। প্রথমে **সাইন আপ** করুন — এই প্রথম অ্যাকাউন্টটাই
স্বয়ংক্রিয়ভাবে অ্যাডমিন হয়ে যাবে।

---

## ধাপ ৪: Netlify-তে ডিপ্লয় করুন

**সবচেয়ে সহজ উপায় — GitHub এর মাধ্যমে:**

1. এই প্রজেক্টের কোড একটা GitHub রিপোজিটরিতে পুশ করুন (`.env` ফাইলটা **push করবেন না** —
   `.gitignore`-এ এটা আগে থেকেই বাদ দেওয়া আছে)।
2. [app.netlify.com](https://app.netlify.com) এ গিয়ে **Add new site > Import an existing
   project** ক্লিক করুন, GitHub রিপোটা সিলেক্ট করুন।
3. Build সেটিংস এমনিতেই ঠিক থাকবে (`netlify.toml` ফাইল থেকে পড়ে নেবে):
   - Build command: `npm run build`
   - Publish directory: `dist`
4. ডিপ্লয় করার আগে **"Add environment variables"** এ ক্লিক করে `.env` ফাইলের প্রতিটা
   `VITE_FIREBASE_...` ভ্যারিয়েবল একে একে যোগ করুন (একই নাম, একই মান)।
5. **Deploy site** ক্লিক করুন। কিছুক্ষণের মধ্যেই একটা লাইভ লিংক পেয়ে যাবেন
   (যেমন `https://your-site-name.netlify.app`)।

**বিকল্প উপায় — Netlify CLI দিয়ে সরাসরি (GitHub ছাড়াই):**

```bash
npm install -g netlify-cli
npm run build
netlify deploy --prod
```

CLI আপনাকে Netlify অ্যাকাউন্টে লগইন করতে বলবে, তারপর `dist` ফোল্ডার ডিপ্লয় করে দেবে। এক্ষেত্রে
Environment variables Netlify সাইটের **Site settings > Environment variables** থেকে ম্যানুয়ালি
যোগ করে নিতে হবে, এবং একবার env var যোগ করার পর আবার `netlify deploy --prod` চালাতে হবে যেন
build-এ সেগুলো যুক্ত হয়।

## ধাপ ৫: ব্যবহার শুরু করুন

1. লাইভ লিংকে গিয়ে **সাইন আপ** করুন — এটাই আপনার অ্যাডমিন অ্যাকাউন্ট হবে।
2. **ইউজার ম্যানেজমেন্ট** পেজ থেকে বাকি স্টাফদের বলুন সাইন আপ করতে, তারপর তাদের রোল/ডিপার্টমেন্ট
   (মার্চেন্ডাইজিং, প্রোডাকশন, স্টোর) নির্ধারণ করে দিন।
3. **প্রোডাকশন** থেকে নতুন স্টাইল/অর্ডার যোগ করুন।
4. **ইনভেন্টরি** থেকে ইয়ার্ন ও এক্সেসরিজের ওপেনিং স্টক যোগ করুন।

## কে কী করতে পারবে

| ডিপার্টমেন্ট | দেখতে পারবে | করতে পারবে |
|---|---|---|
| অ্যাডমিন | সবকিছু | সবকিছু, ইউজার অনুমোদন |
| মার্চেন্ডাইজিং | স্টাইল, ইনভেন্টরি | নতুন স্টাইল তৈরি/এডিট |
| প্রোডাকশন | স্টাইল, ইনভেন্টরি | দৈনিক প্রোডাকশন এন্ট্রি |
| স্টোর | স্টাইল, ইনভেন্টরি | ইনভেন্টরি আইটেম ও স্টক ইন/আউট |

## পরে যা যোগ করা যেতে পারে

- অর্ডার/বায়ার ম্যানেজমেন্ট (PO, ডেলিভারি শিডিউল)
- কর্মী/পে-রোল ও অ্যাটেনডেন্স
- এক্সেল এক্সপোর্ট / রিপোর্ট
- ছবি আপলোড (স্টাইলের স্যাম্পল ছবি)

এই ফাইলগুলো নিয়ে কাজ চালিয়ে যেতে চাইলে যেকোনো সময় আবার এখানে এসে বলুন — নতুন মডিউল বা
পরিবর্তন যোগ করে দেওয়া যাবে।

## আপডেট (নতুন সংযোজন)

এই আপডেটে যা যা নতুন যোগ হয়েছে:

- **অ্যাডমিন সেটিংস** (Admin > Settings): কোম্পানির নাম (বাংলা/English), লোগো আপলোড, ডিফল্ট ভাষা,
  কোয়ালিটি ট্রাফিক-লাইট থ্রেশহোল্ড — সব রিপোর্টের হেডলাইনে এই তথ্য ব্যবহার হয়।
- **দ্বিভাষিক ইন্টারফেস**: সাইডবারের বাটন থেকে বাংলা/English টগল করা যায় (ব্রাউজারে সেভ থাকে)।
- **Excel ও PDF ডাউনলোড**: প্রতিটি তালিকা/রিপোর্ট পাতায় Excel ও PDF এক্সপোর্ট বাটন আছে, লোগো ও
  কোম্পানির নামসহ হেডলাইন অটোমেটিক বসে যায়। এক্সট্রা কোনো পেইড সার্ভিস লাগে না — ব্রাউজারেই তৈরি হয়।
- **কোয়ালিটি মডিউল** (নতুন): দৈনিক QC এন্ট্রি (সেকশন-ভিত্তিক ডিফেক্ট ব্রেকডাউন), ট্রাফিক-লাইট
  ড্যাশবোর্ড, জিরো থ্রেড রিপোর্ট, ফিল্টারযোগ্য রিপোর্ট তালিকা।
- **প্রোডাকশন — ১১টি স্টেজ**: Knitting, Linking, Trimming, Mending, Light Check, Sewing, Wash,
  PQC, Iron, Getup, Packing। নতুন স্টাইল ফর্মে PO নং, স্টাইল নাম/নম্বর, GG, কালার, ইয়ার্ন
  কম্পোজিশন, এবং স্টাইলের ছবি আপলোড যোগ হয়েছে। স্টাইল লিস্টে স্মার্ট সার্চ বক্স আছে (PO/নাম/নম্বর)।
  নিটিং এন্ট্রিতে কোন ইয়ার্নের বিপরীতে কত প্রোডাকশন হয়েছে তা ট্র্যাক হয় (ইয়ার্ন খরচের রিপোর্ট)।
- **সেকশন-ভিত্তিক অ্যাক্সেস**: Admin > User Management থেকে প্রতিটি প্রোডাকশন/স্টোর ইউজারকে
  নির্দিষ্ট সেকশন (যেমন শুধু নিটিং) এসাইন করা যায় — সেই ইউজার শুধু ঐ সেকশনেই এন্ট্রি দিতে পারবে।
- **ইনভেন্টরি — স্টাইল-ভিত্তিক ইয়ার্ন ট্র্যাকিং** (নতুন পাতা: Inventory > Style Yarn Tracking): স্টাইল
  সার্চ করে সেই স্টাইলের বিপরীতে ডাইং অর্ডার, রিসিভড, ব্যালেন্স, সাপ্লায়ার, চালান নং ট্র্যাক করা যায়।
  রিসিভড ইয়ার্ন ওয়াইন্ডিং প্রয়োজন নাকি সরাসরি নিটিং-এ যাবে তা ভাগ করে দেওয়া যায়।
- **ওয়াইন্ডিং কিউ** (নতুন পাতা: Inventory > Winding Queue): সব স্টাইল জুড়ে ওয়াইন্ডিং-পেন্ডিং ইয়ার্নের
  একটাই তালিকা — ওয়াইন্ডিং শেষ হলে এন্ট্রি দিলেই সেই ইয়ার্ন নিটিং-এর জন্য প্রস্তুত হয়ে যায়। ইয়ার্নের
  একক সবসময় **kg**; অন্যান্য আইটেম pcs/dozen/set ইত্যাদিতে রাখা যায়।
- **ড্যাশবোর্ড**: এখন তারিখ-রেঞ্জ দিয়ে "প্যাকড" সংখ্যা ফিল্টার করা যায়, বায়ার দিয়ে চলমান স্টাইল
  ফিল্টার করা যায়, লো-স্টক সেকশন সরানো হয়েছে।
- **এডিট ও ডিলিট**: স্টাইল, ইনভেন্টরি আইটেম, প্রোডাকশন/ইনভেন্টরি এন্ট্রি, কোয়ালিটি এন্ট্রি, ইউজার — সব
  জায়গায় এডিট/ডিলিট অপশন যোগ হয়েছে (রোল অনুযায়ী)।

### জরুরি — ডিপ্লয়ের আগে অবশ্যই করুন

1. **Firestore Rules আবার পাবলিশ করুন**: এই আপডেটে `firestore.rules` ফাইলে নতুন কালেকশনের
   (settings, qualityChecks, zeroThreadReports, yarnAllocations) জন্য নিয়ম যোগ হয়েছে। Firebase
   Console > Firestore Database > Rules ট্যাবে গিয়ে `firestore.rules` ফাইলের পুরো কন্টেন্ট আবার
   কপি-পেস্ট করে **Publish** করুন — নাহলে নতুন ফিচারগুলো Permission denied error দেখাবে।
2. প্রথমবার লগইন করার পর **Admin > Settings**-এ গিয়ে কোম্পানির নাম ও লোগো বসিয়ে নিন।
3. **Admin > User Management**-এ গিয়ে প্রোডাকশন/স্টোর ইউজারদের সেকশন এসাইন করে দিন, নাহলে তারা
   কোনো এন্ট্রি দিতে পারবে না।
4. Netlify-তে নতুন করে ডিপ্লয় করলে `npm install` নিজে থেকেই চলবে — কোনো এক্সট্রা প্যাকেজ যোগ করা
   হয়নি, তাই বিল্ড আগের মতোই কাজ করবে।

## আপডেট রাউন্ড ২

- **ইয়ার্নের হিসাব এখন সম্পূর্ণ পাউন্ড (lb)-এ** — kg আর কোথাও নেই (শুধু accessories-জাতীয় আইটেমে ঐচ্ছিক unit হিসেবে kg রাখা আছে)।
- **নতুন ইয়ার্ন ফ্লো** (Inventory > Style Yarn Tracking): ডাইং অর্ডার → সাপ্লায়ার থেকে রিসিভ (চালানসহ) → ইয়ার্ন স্টোর থেকে ওয়াইন্ডিং বা সরাসরি নিটিং-এ ইস্যু → ওয়াইন্ডিং থেকে নিটিং-এ ফরওয়ার্ড → নিটিং প্রোডাকশন এন্ট্রিতে খরচ — সবকিছু একটা লেজার থেকে স্বয়ংক্রিয়ভাবে ব্যালেন্স হিসাব হয়।
- **নতুন এক্সেসরিজ ফ্লো** (Inventory > Style Accessory Tracking): স্টাইল সার্চ করে এক্সেসরিজ স্টোর থেকে রিসিভ (চালান/সাপ্লায়ারসহ), তারপর নির্দিষ্ট সেকশনে ইস্যু। মেইন লেবেল/কেয়ার লেবেল/সাইজ লেবেল/প্রাইস স্টিকার/পলি স্টিকার/হ্যাংট্যাগ/পলিব্যাগ প্রিসেট আছে কিন্তু নতুন যেকোনো আইটেমও যোগ করা যায়।
- **কোয়ালিটি QC এন্ট্রি**: "সব স্টাইল (মিক্সড)" অপশন, ব্লক (A–M) ফিল্ড, এবং প্রতিটি সেকশনের নিজস্ব ডিফেক্ট তালিকা (Knitting/Linking/Trimming/Mending/Light Check/PQC/Wash/Sewing/Iron/Attachment) — এবং যেকোনো সময় নতুন ডিফেক্ট যোগ করার অপশন।
- **নতুন "Attachment" প্রোডাকশন স্টেজ** যোগ হয়েছে।
- **নতুন Quality Trends পাতা**: ঘণ্টাভিত্তিক (আজ)/দৈনিক/সাপ্তাহিক/মাসিক/বার্ষিক চার্ট, টপ ৫ ডিফেক্ট, সেকশন-ভিত্তিক সারসংক্ষেপ — সব এক্সপোর্টযোগ্য।
- **ড্যাশবোর্ডে নতুন উইজেট**: টপ ডিফেক্ট ও সব সেকশনের কর্মপ্রবাহ (প্রোডাকশন + পাস রেট), তারিখ-রেঞ্জ দিয়ে ফিল্টার করা যায়।
- **সব পাতায় "পেছনে যান" (Back) বাটন** — টপ বারে যোগ হয়েছে (হোম পেজ ছাড়া সব জায়গায় দেখা যাবে)।

### আবার — Firestore Rules পাবলিশ করতে ভুলবেন না
এই রাউন্ডেও `firestore.rules`-এ নতুন কালেকশনের (defectTypes, yarnLedger, accessoryLedger) rules যোগ হয়েছে। Firebase Console-এ গিয়ে আবার পুরো ফাইলটা কপি করে Publish করুন।

নতুন সেকশন যোগ হয়েছে: **Yarn Store** ও **Accessories Store** — Admin > User Management থেকে স্টোরের স্টাফদের এই সেকশনগুলো এসাইন করে দিন যদি তারা নির্দিষ্ট কাজে সীমাবদ্ধ থাকুক।

## আপডেট রাউন্ড ৩

- **লগইন "pending" বাগ ফিক্স**: প্রোফাইল এখন লাইভ শোনে (আগে একবার লোড হত) — অ্যাডমিন অনুমোদন দিলে সাথে সাথে দেখাবে, রিলগইন লাগবে না।

## আপডেট রাউন্ড ৪

এই রাউন্ডে যাচাই করে দেখা গেছে যে আগের রাউন্ডের অনেক ফিচার (রিসিভ করার সময়েই ব্লক সিলেক্ট, ব্লক থেকে ইস্যু করলে স্টক কমা, StyleYarnTracking থেকে আলাদা "Dyeing Order" অপশন সরানো, ইয়ার্ন সবসময় lb-তে, দুইটা আলাদা স্টক সিস্টেম না থাকা) ইতিমধ্যে ঠিকভাবে কাজ করছিল। যা সত্যিকারের ঘাটতি ছিল তা এই রাউন্ডে ঠিক করা হয়েছে:

- **স্টাইল লিস্ট পেজ থেকে ডিলিট করলে এখন সম্পূর্ণ cascade হয়** — আগে স্টাইল ডিটেইল পেজ থেকে ডিলিট করলে ইয়ার্ন/এক্সেসরিজ লেজার ও প্রোডাকশন এন্ট্রি ঠিকভাবে মুছে যেত, কিন্তু স্টাইল লিস্টের কুইক-ডিলিট বাটন শুধু স্টাইল ডকুমেন্টটাই মুছত (baki সব "orphan" হয়ে থেকে যেত, রিপোর্টে ভেসে থাকত) — এখন দুই জায়গা থেকেই সম্পূর্ণ cascade delete হয়, সতর্কতাসহ।
- **এন্ট্রি এডিট করার সুবিধা** — এখন ইয়ার্ন ও এক্সেসরিজ লেজারের যেকোনো এন্ট্রি (কোয়ান্টিটি, তারিখ, ব্লক, চালান, সাপ্লায়ার, নোট) সরাসরি এডিট করা যাবে, শুধু ডিলিট না — অ্যাডমিন বা ইনভেন্টরি-এরিয়া-অ্যাডমিনের জন্য।
- **নতুন: ব্লক ম্যানুয়াল সংশোধন (Reconciliation)** — Style-wise Yarn Tracking পেজে এখন একটা "ব্লক সংশোধন" ফর্ম আছে (শুধু অ্যাডমিন/ইনভেন্টরি-এরিয়া-অ্যাডমিনের জন্য) যেখানে সরাসরি কোনো ব্লকের স্টক যোগ/বিয়োগ করা যায় (ফিজিক্যাল কাউন্ট মেলাতে বা পুরনো ভুল ডেটা ঠিক করতে) — কারণ উল্লেখ করা বাধ্যতামূলক। এটা Item Detail-এর স্টক হিসাবেও (মোট স্টক, ব্লক-ভিত্তিক ব্রেকডাউন, স্টাইল-ভিত্তিক ব্যালেন্স) স্বয়ংক্রিয়ভাবে যুক্ত হয়ে গেছে।
- **Winding Queue থেকে এডিট/ডিলিট** — প্রতিটি সারিতে এখন "এডিট/ডিলিট →" লিংক আছে যেটা সরাসরি সেই স্টাইলের Yarn Tracking পেজে (সেই স্টাইল প্রি-সিলেক্টেড অবস্থায়) নিয়ে যায়, যেখানে পুরো এডিট/ডিলিট সুবিধা আছে।

### আবার — Firestore Rules পাবলিশ করতে ভুলবেন না
এই রাউন্ডে নতুন `blockAdjustIn`/`blockAdjustOut` এন্ট্রি টাইপের জন্য rules-এ বিশেষ পারমিশন যোগ হয়েছে (শুধু অ্যাডমিন/ইনভেন্টরি-এরিয়া-অ্যাডমিন এগুলো তৈরি করতে পারবে)। Firebase Console-এ গিয়ে আবার পুরো `firestore.rules` কপি-পেস্ট করে Publish করুন।
